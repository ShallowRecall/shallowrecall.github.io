ESXi 存储一夜消失:SATA 控制器直通引发的"血案"复盘

发表于2026-10-25|更新于2026-10-25|技术笔记复盘类
|阅读量:

📝 ESXi 存储一夜消失:SATA 控制器直通引发的”血案”复盘

💡 如果你的 ESXi 也出现”数据存储归零、虚拟机无效、但系统还能 SSH”——大概率不是数据丢了,先看本文第 3 节。

0. 背景

家里的 All-in-One 主机:

项目配置
平台Intel J4125(Gemini Lake)小主机
内存16 GB
系统盘金百达 512G SATA SSD(ESXi 系统盘 + datastore1)
网卡4 × Intel I226 2.5G
虚拟化VMware ESXi 8.0.2(sysin.org 打包镜像)
虚拟机爱快软路由(3 个物理网卡 PCI 直通)

某次重启 ESXi 后,打开网页:

  • 存储页面:数据存储计数 0——空空如也
  • 虚拟机页面:爱快 VM 显示「无效」,配置路径指向 /vmfs/volumes/4f02eeb0-.../iKuai/iKuai.vmx

512G 的 SSD 就装在机器里,ESXi 却像一台”没插硬盘”的裸机一样运行着。
更诡异的是:系统还能开机、SSH 能登、密码和 IP 都还在——配置没丢,只是存储消失了。

1. 诊断决策树

1.1 第一层:不是”卷丢了”,是”盘丢了”

SSH 登录(幸好 SSH 和密码配置还在),三条命令定位问题层级:

关键判断:如果只是 VMFS 卷损坏/未挂载,至少能看到块设备(如 t10.ATA_____xxx)。连设备节点都没有,说明问题在存储驱动层之下——要么驱动没加载,要么控制器没交给 ESXi 内核。

1.2 第二层:干扰项——VIB 签名告警

dmesg 里翻到一条触目惊心的 ALERT:

几乎所有 VIB 都”验签失败”?!第一反应:

  1. Secure Boot 开了,第三方打包镜像被拒?
  2. 启动分区数据损坏,签名校验不过?

逐项排除:

再深挖发现 /bootbank 指向了 /tmp/_bootbankxabv0jit(内存中的降级空目录),vdf -h 里所有挂载点全是 Ramdisk——根分区、/etc、osdata、configstore 全部跑在内存里。

⚠️ 此时很容易得出错误结论:”因为启动分区坏了 → VIB 验签失败 → 驱动不加载 → 看不到盘”。
因果其实是反的,这是本次排障最大的陷阱,下一节揭晓。

1.3 第三层:实锤——PCI Passthrough 劫持了 SATA 控制器

不纠结告警,直接看”谁在管这块 SATA 控制器”:

passthru! 这块承载着系统盘的 SATA 控制器,在开机早期被 PCI 直通层(VM Passthrough) 从 ESXi 内核手里抢走了。

内核日志给出了精确时间线:

1.4 完整因果链(倒推)

破案补充:这台机器爱快 VM 一直用 3 个 I226 网卡直通,一切正常——因为那 3 个口上没有系统盘。某次把 SATA 控制器也加入了直通(可能是想给 NAS 虚拟机直通硬盘),重启后系统盘控制器直接消失,于是”存储一夜蒸发”。

2. 修复

2.1 运行时恢复(不重启)

解除直通的那一秒,所有分区瞬间回归:

爱快虚拟机也从「无效」恢复为正常,/bootbank 符号链接指回真实分区。

🐛 顺带踩了个工具坑:老牌命令 vmkchdev -v 0000:00:12.0 在 8.0.2 上有进制转换 bug——把 16 进制的槽位 12 当成 10 进制转换成了 0c,报 Did not find PCI device at 0000:00:0c.0。遇到这个错直接用上面的 localcli hardware pci pcipassthru set 即可。

2.2 持久化(否则重启复发)

运行时的修改此时只会写进内存里的临时 bootbank,重启即失。所以:

ESXi 8 的持久化链路:hostd/configstore(内存)→ auto-backup.sh → state.tgz(AES 加密)→ BOOTBANK1 分区,下次开机由引导程序读回。

2.3 重启验证

另外两处顺手修复:

  • 系统时间停在 2012(主板纽扣电池没电的典型症状):配置 NTP esxcli system ntp set -e true -s 203.107.6.88 -s 106.55.184.199
  • /etc/vmware/passthru.map 末尾有一条手工添加的 8086 31e3 d3d0 fasle(还拼错了 false)——这条只是直通重置方式的提示表,不是本次故障根因,但留着容易误导后人,建议清理。

3. 教训与红线

  1. 系统盘所在控制器,永远不要开直通。 开直通前先 vmkchdev -l 确认设备上挂着什么。
  2. 直通的代价是”重启后才爆”: 界面上点完开关一切正常,提示”需重启”,重启完才崩——间隔让人无法把两件事关联起来。
  3. “所有 VIB 验签失败” ≠ 镜像坏了。 它可能是 bootbank 不可达的结果。看到这条 ALERT 先查 /bootbank 指向哪、vdf -h 是不是全内存盘,再下结论。
  4. 配置”还在”但 esx.conf 变干净 也是同款症状:密码/网络来自 state.tgz 的其他部分,而 esx.conf 被 configstore 同步降级成了默认值。
  5. 修完务必做持久化验证(重启一次),并留一份 state.tgz 备份到别处:

4. 一图总结

排障工具速查:lspci / vmkchdev -l(设备归属)/ vmkload_mod <mod>(手动加载驱动)/ esxcli storage core adapter rescan --all / vdf -h(看内存盘)/ dmesg(时间线)。
