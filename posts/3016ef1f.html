baoyu-xhs-images实战：把长内容拆成有阅读节奏的图片卡片

发表于2026-10-15|更新于2026-10-15|技术笔记开发工具宝玉Skills
|阅读量:

返回总教程

baoyu-xhs-images 不只是“小红书封面生成器”。这一版本面向社交图片卡片序列，也可处理小绿书、微信图文等场景；关键是把内容拆成读者愿意逐张看完、又不会在每页迷失上下文的结构。

本文基于固定提交源码核对；案例是操作示例，非付费服务或账号实测。未生成图片、登录平台或发布内容，也不保证流量效果。

一、场景与边界

适合工具清单、教程步骤、概念解释、产品比较和经验分享。技能简介声明一至十张图片，分析步骤通常建议二至十张；实际数量应由内容与用户确认决定，不要为了凑满十张重复讲同一观点。

它有 12 种风格、8 种布局、3 种可选覆盖配色。风格如 notion、chalkboard、study-notes、screen-print、sketch-notes；布局如 sparse、balanced、dense、list、comparison、flow、mindmap、quadrant。风格、布局和配色是不同问题：把 notion 换成马卡龙配色，不会自动变成另一套绘画规则。

输出是图片卡片，不包括平台发布。源码中与流量相关的画布建议属于设计启发，不是经过本教程验证的平台算法事实。遇到测评和个人经验内容，必须使用真实提供的经历，不能把 Agent 创作的体验写成用户亲测。

二、前置依赖与按需安装

需要具备读写文件能力的 Agent、可用图像后端，以及有使用权的源内容和参考图。多页一致性依赖参考图支持，选后端时应先核实，不能等画完第二页才发现无法传入首图。

经仓库 README 核实的安装入口：

Claude Code 用户可将 codex 替换为 claude-code。

仅选择 baoyu-xhs-images，缺少图像后端再安装 图片生成。不要把整仓安装当成必要条件。该命令取当前仓库内容，不锁定本文提交；固定版本可将完整技能目录放入 Codex 项目的 .agents/skills/baoyu-xhs-images/。

本文不执行任何安装或生成。账号权限、API 费用和资料上传范围由用户事先确认。

三、输入输出与两套 A/B/C

输入可以是笔记、文章、清单或明确主题。最好给出受众、必须保留的结论、证据来源、目标张数和期望行动，例如“让读者按清单检查备份设置”，而不是“做爆款”。

输出目录是 image-cards/{topic-slug}/，不是根据旧名称猜出的 xhs-images/。其中有源内容、analysis.md、outline.md、逐张提示词和 PNG；只有详细模式会额外生成三份 outline-strategy-a/b/c.md，有参考图时才有 refs/。

源码有两套 A/B/C，需要分清：

概念ABC
内容策略故事驱动信息密集视觉优先
确认路径快速确认自定义详细模式

走“确认路径 A”不意味着强制采用“故事策略 A”。快速确认只是接受当前推荐，推荐本身可能是信息密集。详细模式才会生成三套结构不同、推荐风格也不同的大纲供比较。

四、可复制的 Agent 请求

如果只需要策划，加上“本轮只讨论并保存大纲，不调用图像后端”，可以先审查信息拆分再决定是否出图。

五、案例：六张笔记备份卡片

第一张提出问题：“同步不等于备份”。第二张解释同步删除会传播；第三张说明版本历史的作用；第四张列出独立备份要求；第五张给恢复演练步骤；第六张给自查清单。这里不虚构用户曾经丢失文件，也不承诺某产品永远可靠。

分析阶段将源材料保存并提取受众、核心价值和逐张阅读关系。策略选信息密集，封面用 sparse，解释页用 balanced，清单页用 list。不要把全套都设置为 dense：封面承担入口功能，末页承担回顾功能，内容密度应有变化。

确认阶段选择自定义路径，明确六张、中文、风格、配色和后端。没有偏好文件的首次交互流程应先完成设置，不应直接分析出图；只有用户明确要求非交互模式时，才使用对应默认行为，不自动替用户创建偏好文件。

进入生成后先写完每一张最终提示词并检查文件存在。首图是整套视觉锚点，先生成并验收；后续卡片把首图作为参考，才能减少颜色、角色与装饰漂移。普通无用户参考的流程里首图不传参考图；若用户另给品牌参考，源码专门的参考图规则允许把它用在首图，后续仍只沿用首图，不反复叠加品牌参考造成冲突。

第二至第六张可按批次处理，默认并行数四，但首图依赖必须先满足。失败只重试失败项一次。后端即使支持会话标识，也不能用会话标识替代首图参考链；不支持参考图的后端要提前说明限制，而不是声称有同等一致性。

六、画布与配置

画布参考建议纵向 3:4，也提供方形和更长比例。底部约 10%、右上和右下区域不放关键信息，实际平台界面会变，发布前仍需用目标平台预览验证。参考文件中的示例像素仅是设计规格，不应写成所有模型均能精确输出的保证。

偏好依次读取项目 .baoyu-skills/baoyu-xhs-images/EXTEND.md、XDG 配置目录、用户 $HOME/.baoyu-skills/baoyu-xhs-images/EXTEND.md。常用字段包括 preferred_style、preferred_layout、preferred_palette、language、preferred_image_backend、generation_batch_size 和水印配置。

knowledge-card 等预设是风格加布局的快捷组合，不等于固定张数。首次交互设置与每次内容确认也不同：保存偏好只是减少重复输入，不自动授权跳过确认。若用户明确要求直接生成，Agent 仍需先报告本次采用的策略、布局、风格、配色、张数与后端。

七、验收与排错

  • [ ] 每张有独立重点，整套能顺序阅读，不存在前后矛盾。
  • [ ] 卡片中的经验、结论和数据来自真实输入。
  • [ ] 首图作为参考链的起点，后续没有混入冲突参考。
  • [ ] 封面和结尾不过密，手机尺寸下正文可读。
  • [ ] 提示词、图片和大纲编号一致，修改前保留备份。
  • [ ] 未自动发布，公开附件中没有无关参考图和个人资料。

整套风格漂移：检查后续任务是否实际传入首图，而不是只在提示词说“保持一致”。每张都像海报、知识太少：检查是否误选视觉优先策略或低密度布局。出现编造经历：回到输入和大纲，改为事实清单，不只是删一处措辞。错别字：先改提示词，再用新路径重生成，不程序覆盖位图文字。重复页或漏页：比对大纲编号与输出清单，只补缺失项。

Obsidian 与 Hexo 可用普通 Markdown 顺序嵌入卡片；附件要进入发布链，主题也可能对图片做裁剪，应预览真实文章页。

八、相关技能与源码

文章封面 适合单张入口图；知识漫画 适合人物叙事；信息图 适合单张高密度总览。
