baoyu-slide-deck实战：制作可审阅、可重生成的阅读型幻灯片

发表于2026-10-15|更新于2026-10-15|技术笔记开发工具宝玉Skills
|阅读量:

返回总教程

baoyu-slide-deck 先写大纲和逐页提示词，再生成页面图片，最后合并为 PPTX 与 PDF。源码明确偏向“阅读和分享型”幻灯片，而不是只放关键词、由演讲者口头补充的现场演讲稿。

本文基于固定提交源码核对；案例是操作示例，非付费服务或账号实测。未生成幻灯片、运行合并或发布文件。

一、场景与边界

适合技术方案解读、知识分享、研究概要和可独立阅读的产品介绍。页面需要在没有讲解人的情况下成立，所以每页应有清楚的结论和足够上下文，但并非把整段文章缩成很小的字体。

最需要澄清的是“PPTX”的含义。已经核对的 merge-to-pptx.ts 使用 PptxGenJS，把每张页面图片作为整页图像加入幻灯片；不是把标题、文本框和图表分别转成可编辑元素。对应提示词还会作为备注加入。能在 PowerPoint 打开，不等于能逐条修改图内文字。

如果目标是可编辑企业模板、原生表格或图表，请选择专门的演示文稿制作工具，而不是寄希望于合并脚本自动恢复图片中的布局。若是需要精确工程关系，先用 技术图解 制作可核查的图，再明确后续使用方式。

二、前置依赖与按需安装

需要文件读写型 Agent、可用图像后端，以及合并阶段的 Bun 运行环境与脚本依赖。源码规定优先 bun，否则 npx -y bun；PPTX 合并实际导入 pptxgenjs。运行环境不等于图像后端授权，两者分开准备。

本教程不执行安装、登录、生成或发布。正式批量生成前，确认页面数、后端、费用范围和资料上传权限，尤其不要把公司保密资料未经授权传给外部服务。

三、输入输出与阶段控制

输入可为文章、说明文档或明确主题，最好提供受众、目标、必须保留的信息和篇幅。技能建议通常为八至二十五页，最多三十页；这是源码的页数约束和建议，不是“长文越长页数越多就越好”。

输出目录为 slide-deck/{topic-slug}/，其中包含源文件、analysis.md、outline.md、prompts/NN-slide-{slug}.md、页面 PNG、主题 PPTX 和 PDF。编号表达页序，slug 表达内容；插页后改编号，不必改内容 slug。

技能支持只到大纲、只到提示词、从已有提示词开始生成，以及重生成指定页。适合先完成文字审阅再付费出图。不要把阶段控制理解成绕过确认：默认仍应先确认风格、受众、页数和审阅方式。

四、可复制的 Agent 请求

续作时可以要求“沿用已确认大纲，只写提示词，待我再次确认后生成”，而不需要手工编写脚本参数。

五、案例：十二页代码评审说明

先把内容拆成逻辑段落：为什么评审、提交前准备、描述变更、评审关注点、沟通方式、处理反馈、重新验证和最终合并。页数预算留给封面、关键流程和总结，但不要用重复观点填满十二页。

分析后可以推荐 blueprint 或 sketch-notes，前者偏技术结构，后者偏教学说明。源码有 17 种预设，每种由纹理、情绪、字体与密度四维组成；自定义模式才需进一步确认四个维度，不必每次都从零选。

确认完后写 outline.md，其中带统一的 STYLE_INSTRUCTIONS。逐页提示词从大纲继承这份规则，不应每页重新随机选择风格。每页说明标题、内容、图形构成和布局，保存到 prompts/ 后再出图。

图像阶段默认可分批处理，常规并发建议四；实际以所选后端和运行时支持为准。原生批处理优先，其次运行时并行，最后才串行。失败只重试失败页一次，不重做成功页。支持会话的后端可传入统一会话标识，不支持则不编造会话参数。

六、配置与源码中的实用注意点

偏好依次来自项目 .baoyu-skills/baoyu-slide-deck/EXTEND.md、XDG 配置目录和用户 $HOME/.baoyu-skills/baoyu-slide-deck/EXTEND.md。与部分图像技能不同，这个技能缺少偏好文件时可以使用默认值继续，不要求先完成阻塞式初始设置。

常用字段是 preferred_style、preferred_audience、language、preferred_image_backend 和 generation_batch_size。保存偏好不等于免确认。已有主题目录时还应先让用户决定重新写大纲、重做图片、备份重做或退出。

源码的确认说明希望一次询问五项，但具体 Agent 工具可能每次最多四题，应分两轮保留全部决策，不能为了适配工具丢掉“是否审阅提示词”这一项。

另一个脚本层注意点是，PPTX 图片筛选采用以数字加 -slide- 开头的命名模式；备份文件如果仍保留这个开头并放在同一目录，也可能被纳入合并。合并前请 Agent 核对实际文件清单，把归档候选放到不被扫描的备份子目录，避免同一页重复进入演示稿。

七、验收与排错

  • [ ] 不靠讲解也能理解每页结论，阅读顺序完整。
  • [ ] 十二页计划与实际图片、PPTX、PDF 页数一致。
  • [ ] 字体、配色、比例和边距统一，数据不超出输入。
  • [ ] PPTX 可打开，但明确属于图片式页面。
  • [ ] 备注中的提示词不含秘密、内部说明或未授权资料。
  • [ ] 备份图没有混入正式合并，最新修订页已经重新打包。

文字无法在 PowerPoint 编辑：这是设计边界，不是导出失败。漏页或重复页：核对编号模式和备份文件，再合并。错别字：改对应页提示词并另存新候选，不能程序覆盖位图中的文字。输出比例奇怪：检查图像比例是否与脚本的 16:9 匹配。文件太大：验收后压缩交付图，但保留原图和提示词，避免压缩造成不可逆损失。

Obsidian 和 Hexo 可嵌入单页图片并链接 PDF/PPTX；要检查附件同步和下载链接，不只检查 Markdown 正文能否打开。

八、相关技能与源码

信息图 适合单页总结；知识漫画 适合有角色的解释；图片压缩 用于交付优化。
