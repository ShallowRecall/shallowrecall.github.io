baoyu-danger-x-to-markdown实战：在授权边界内归档推文与长文

发表于2026-10-15|更新于2026-10-15|技术笔记开发工具宝玉Skills
|阅读量:

返回总教程

baoyu-danger-x-to-markdown 用于把 X/Twitter 推文、线程和 X Articles 转成带 YAML 元数据的 Markdown。名字中的 danger 不是装饰：实现使用逆向分析的非官方接口，接口随时可能变化，也可能带来账号限制。

本文基于固定提交源码核对；案例仅为操作示例，非付费内容、账号或接口实测。写作过程中未登录、提取 Cookie、调用接口或生成归档。

一、什么时候用，什么时候不用

适合保存自己有权查看的公开推文、技术讨论串和长文，形成可搜索的资料库。相较复制一段截图，Markdown 更便于检索原话、保存来源和继续翻译。

它不提供官方 API 的稳定性保证，不能承诺某条线程一定完整，也不能保证引用的推文仍然存在。内容删除、隐私限制、订阅权限和接口调整，都可能让正文或附件缺失。用户能在浏览器看到某页，也不意味着脚本当前接口一定支持它。

不要用该工具绕过登录、访问控制或付费权限；不要导入别人的会话凭证。归档成功也不等于获得转载授权。个人研究资料和公开发布文章应分开，尤其不能把私密账号内容或 Cookie 缓存随 Hexo 发布。

二、前置依赖与按需安装

需要能执行文件工作流的 Agent、Bun 或可用的 npx，并且能够以自己的账号正常访问目标内容。脚本入口是完整技能目录中的 scripts/main.ts，运行时优先 Bun，否则允许 npx -y bun。

最新安装不等于固定快照，安装命令本身不会锁定本文版本。若必须复现本文，应使用提交 1567581c26ec29f4216c6e6835415bf30343b0e3 的源码目录，并让 Agent 核查实际运行版本。本文不要求安装任何所谓“X 官方 SDK”，也不把非官方接口包装成官方支持。

三、同意流程必须先于登录与转换

源码在执行登录刷新和转换之前调用 ensureConsent。它会读取本地 consent.json；有效记录需要版本、已接受状态、接受时间，以及 disclaimerVersion: "1.0" 等字段。文件不存在、无效或免责声明版本变化时，必须向用户说明风险并征求选择。

风险说明至少应包含：这是非官方逆向接口；X 调整接口可能导致失效；没有官方支持和保证；可能出现账号限制。用户拒绝，就停止，不能替用户勾选同意。已经接受的情况下，仍会显示此前接受时间及警告。

在 Windows 上，源码按 %APPDATA%/baoyu-skills/x-to-markdown/consent.json 定位；macOS 使用 ~/Library/Application Support/baoyu-skills/x-to-markdown/，Linux 默认使用 ~/.local/share/baoyu-skills/x-to-markdown/。X_DATA_DIR 可改变数据目录，Linux 也尊重 XDG_DATA_HOME。

非交互执行时若缺同意记录，脚本会报错，不会替你完成接受。Agent 只能在用户明确接受后记录同意；不能为了让流水线通过而预填接受状态。这里故意不提供“直接创建已同意文件”的快捷命令。

四、登录态与配置如何管理

SKILL 列出的凭证方式包括环境变量 X_AUTH_TOKEN、X_CT0，以及 Chrome 登录后在本地缓存 Cookie。它们是会话凭证，不是可公开的普通配置。不要把真实值写进 Markdown、聊天示例、Git 提交或截图；不要请求 Agent 把它们打印出来排错。

脚本支持 --login，仅刷新 Cookie 后退出，不会顺便归档文章。但即使只刷新登录态，同意检查仍然执行。登录失败应回到用户本人可见的正常登录流程，不提供绕过验证或复制他人凭证的方案。

五、输入输出与可复制请求

输入支持 x.com/<user>/status/<id>、twitter.com/<user>/status/<id> 和 x.com/i/article/<id>。默认推文目录形态是 x-to-markdown/{username}/{tweet-id}/{content-slug}.md；文章 URL 没有用户名时，脚本使用文章 ID 参与目录组织。给出明确输出文件路径，可避免依赖自动命名细节。

Markdown 通常包含来源 URL、作者、推文数量等元数据；长文和推文的字段并不完全相同，不要强行要求每个输出都含 tweetCount。启用媒体下载后会建立 imgs/、videos/ 并改写相对链接。JSON 模式主要便于读取实际结果路径，不能把某个固定字段当作所有内容类型都一样的保证。

六、操作案例：归档一组技术讨论

假设你在自己的 X 登录会话中看到一位开发者的五段技术说明，想保存供以后写文章时核对。这里的“五段”是案例设定，不是实测结果。

  1. 确认权限与风险。 提供线程的完整地址，确认是自己可访问内容。Agent 完成免责声明与偏好确认，不直接开始网络请求。
  2. 获取文本。 先不下载媒体，减少不必要的请求和磁盘占用。读回 Markdown，核对作者和链接，检查输出是否覆盖预计的五段；若少了两段，应报告缺失，不补写猜测内容。
  3. 区分正文与引用。 若原推文引用其他作者观点，保留归属关系，不能把引用合并成主作者结论。技术文章里的配图说明也不等于图片内容已被识别。
  4. 决定媒体归档。 用户确认需要离线阅读后才下载。源码会尝试复用与目标 URL 匹配的现有 Markdown 来本地化媒体，所以不要假定第二次一定重新抓取正文，也不要随意改掉来源元数据。
  5. 验证资源与留存。 检查图片、视频文件是否实际存在，记录仍保留远程 URL 的附件。保持整个目录移动，避免 Obsidian 中的图片相对路径失效。
  6. 另写发布稿。 需要引用时新建自己的文章，标注原作者与原链接，只引用必要片段。不要直接给整份归档加 publish: true，更不要把会话文件带进博客。

七、验收清单

  • [ ] 免责声明与当前版本同意状态有效，未替用户接受。
  • [ ] 只使用本人授权会话，登录态没有进入教程或输出报告。
  • [ ] 来源 URL、作者、线程顺序能够与原内容对应。
  • [ ] 已明确缺失或不可访问内容，没有模型补全伪装原文。
  • [ ] 下载的媒体可打开，未下载的远程资源已注明。
  • [ ] 正文和敏感数据目录分离，Hexo 不会发布凭证。
  • [ ] 输出路径以实际结果为准，重跑前已保护人工整理稿。

八、排错顺序

Consent required。 先恢复明确同意流程；这不是网络故障，不应通过改代码或伪造同意记录“修复”。

Missing auth cookies。 检查当前授权登录态是否过期，由用户重新正常登录。不要将真实 X_AUTH_TOKEN、X_CT0 粘贴进公开工单。

浏览器能看，脚本失败。 可能是接口变更、内容类型不匹配或账号请求限制。保存脱敏错误摘要，核查固定版本与新版本差异；不要对同一失败目标无限高频重试。

媒体下载后内容没有更新。 源码可能复用了已有归档。若目标是刷新正文，应明确告诉 Agent先验证旧文件及 URL，再选择新的输出路径，而不是把媒体本地化误当成内容同步。

九、相关技能与固定来源

  • 网页转 Markdown：通用浏览器采集方案，也应遵守访问权限。
  • 文章翻译：在来源准确的前提下生成译文。
  • Markdown 排版：整理自己的二次文章。
