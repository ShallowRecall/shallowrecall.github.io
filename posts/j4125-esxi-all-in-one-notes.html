🧭 J4125 全闪 All-in-One 折腾笔记:ESXi + iStoreOS + 飞牛 + Debian + Windows Server

💡 前传:《ESXi 存储一夜消失:SATA 控制器直通引发的”血案”复盘》——建议先读,本文直接从事故修复后开始。

1. 硬件与总架构

项目配置备注
CPUIntel J4125(4C4T)Gemini Lake,VT-d 可用 ✅
内存16 GB拆机笔记本条
系统盘512G SATA SSDESXi 8.0.2 + datastore1(剩 ~350G)
数据盘希捷 2T(USB 3.0 硬盘盒)保留原有 NTFS 数据,直通给 NAS VM
网口4 × I226 2.5Gvmnic0 管理,vmnic1/2/3 直通
无线Intel AX210(M.2→Mini-PCIe 转接)直通给 OpenWrt 做 AP

网络设计原则:管理口与业务口分离。 vmnic0(管理)+ 所有 VM 的 e1000 虚拟网卡走 vSwitch0 → 小米路由器网段(192.168.31.x);vmnic1/2/3 物理直通给 OpenWrt 做未来的 WAN/LAN。这样无论路由 VM 怎么折腾,ESXi 管理口永不失联——血泪教训。

2. 镜像归档体系(重装自由的基础)

所有镜像统一归档,生成 SHA256SUMS.txt + README.md(版本、官方源、重装步骤)。核心纪律:

  • 能下官方源绝不第三方;sysin 打包镜像仅 ESXi 本体(已装好的不再动)
  • 大体积 ISO(WinServer 7.8G)只存 ESXi datastore1/iso/,本地不留
  • 每次系统装好,顺手 auto-backup.sh 拉一份 state.tgz 到归档

3. 虚拟机 ①:iStoreOS(OpenWrt 软路由 + WiFi AP)

3.1 镜像转换(img → vmdk)

iStoreOS 只发 raw img,ESXi 不能直接用,需转 streamOptimized VMDK:

选 iStoreOS 而非官方 OpenWrt 的理由:中文生态 + 应用商店,而且 LAN 默认 DHCP 客户端模式——官方 OpenWrt 首启会在局域网广播 192.168.1.x 的野 DHCP,怼上家里现有网段就是事故。

3.3 找 IP 的三种姿势(没有 VMware Tools 时)

  1. esxcli network vm port list --world-id <wid> 拿到 VM 的 MAC
  2. 全网段并 ping 一轮后 arp -a | grep <MAC> 反查 IP
  3. 兜底:在 vSwitch0 上建临时 portgroup + vmk(如 192.168.100.2/24)直连 VM 的默认网段

3.4 初始配置(SSH)

iStoreOS 有个反直觉的坑:网页 LuCI 用默认密码 password 能进,SSH 用它却 Authentication failed(root 密码实际未设置,LuCI 有回退)。正确姿势:先在网页 系统→管理权→路由器密码 设置密码,SSH 才通。

3.5 AX210 直通排障实录

AX210 走 M.2→Mini-PCIe 转接卡插入主板。现象:PCIe(WiFi)与 USB(蓝牙)双双无踪影,lspci/vmkchdev -l/usbarbitrator 日志三处确认为零。

诊断逻辑:

ESXi 侧知识:ESXi 没有任何 Wi-Fi 驱动,无线网卡永远不可能变成宿主机的 vmnic,唯一玩法是 PCI 直通给 VM。所以宿主机层面 lspci 能看到设备就算”成功”,剩下的交给 OpenWrt 的 iwlwifi。

4. 虚拟机 ②:飞牛OS fnOS(NAS)

  • 官方 ISO 直链藏在 fnnas.com/download 页面 JS 里(iso.liveupdate.fnnas.com/.../fnos_Mainland-PE_x86_1.2.0800_2778.iso)
  • ⚠️ 2026 年起 CDN 全面鉴权:未登录时 curl/PowerShell/.NET/真实浏览器直访一律 403(TLS 指纹 + 账号态双重校验),必须在官网登录账号后才能下载
  • VM:2C/5G/60G 精简盘,EFI + CD-ROM 挂 ISO,中文向导两分钟装完
  • 2T 希捷走 USB 设备直通(见 §6)

ESXi 侧下载大文件的三个坑

  1. ESXi 没配 DNS → wget: bad address;esxcli network ip dns server add --server 223.5.5.5(小米路由器对 ESXi 的 DNS 查询不响应,别用 .1)
  2. 解析出 IPv6 → ESXi 无公网 v6,握手挂起;本地解析 IPv4 写入 /etc/hosts 强制走 v4
  3. busybox wget 的精简 TLS 握不上 Akamai → error getting response;ESXi 又没有 curl → 最终方案:本机下载 + 内网 scp(千兆 ~80MB/s,7.8G 约 2 分钟)

6. USB 硬盘直通给 NAS(保留数据的关键操作)

ESXi 默认扣留 USB 存储设备(usbarbitrator 服务,留给 VM 直通),数据存储里看不到是正常现象:

热插拔教训:SATA/PCIe 设备不要带电插,USB 盘插入瞬间的 5V 冲击曾把这台小主机直接拉挂(机械盘启动电流 >2A)。要加盘,先关机。

7. 路由切换:爱快 → OpenWrt(可回退)

最后一步,物理动作 + 配置联动:

回退方案:爱快 VM 与其 3 个网卡直通原封不动,网线插回爱快对应网口、光猫改回路由模式即可。

8. 避坑清单(按血泪程度排序)

#坑一句话解法
1系统盘控制器被开直通,存储全灭vmkchdev -l 查归属;直通前确认盘上没有 BOOTBANK/OSDATA
2ESXi 永不支持 Wi-Fi 当物理网卡只能 PCI 直通给 VM(iwlwifi)
3fnOS ISO 下载全 403官网登录后下载,任何脚本直下都会被指纹墙拦
4OpenWrt 首启野 DHCP用 iStoreOS(LAN 默认 DHCP 客户端)或首启先断网配好
5ESXi 下载:DNS/IPv6/TLS 三连坑配 223.5.5.5 + hosts 锁 v4 + 终极方案本机 scp
6iStoreOS 网页密码≠SSH 密码网页设完密码 SSH 才可用
7USB 盘在数据存储里”消失”usbarbitrator 机制,直通给 VM 就好
8带电插 SATA/机械盘 → 整机掉电加盘必关机
9主板电池没电 → 时间回 2012换 CR2032 + 配 NTP
