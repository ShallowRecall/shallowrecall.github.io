宝玉 Skills 实战教程：从安装到搭建 AI 内容工作流

发表于2026-10-15|更新于2026-10-15|技术笔记开发工具
|阅读量:

写完一篇技术文章，真正耗时的部分往往还没结束：整理标题、调 Markdown 格式、做封面、画解释图、压缩图片，再分别准备博客、公众号和分享材料。

宝玉的 baoyu-skills 把这些重复工作整理成了 Agent 能读取并执行的技能。你给它文章和约束，它根据技能里的流程、参考资料与脚本完成任务。最值得学会的，不是记住二十多个名字，而是把适合自己的几个技能串起来。

这篇教程面向已经能使用 Codex 或 Claude Code、但还没有形成 Skills 工作习惯的读者。完成前半部分，你就能安装一个技能并验证输出；继续往下，可以把同一篇文章加工成博客稿、封面、知识卡片和分享幻灯片。

版本说明：核对日期为 2026 年 10 月 15 日。本文基于仓库提交 1567581c26，插件市场清单版本为 2.5.2。实际执行了技能发现命令并核对脚本与配置；图片生成及社交发布案例是操作示例，不代表已经替读者调用付费接口或发布内容。

一、先理解三个角色：Agent、Skill、工具

假设你对 AI 说：“把这篇文章做成一套小红书知识卡片。”

只有一句提示词时，AI 需要临时决定怎么分段、选什么风格、每张卡写多少字、把文件放在哪里。Skill 则把这些约定提前写好了，例如先分析内容、给出大纲、固定视觉风格、保存提示词，再生成图片。

角色在这项任务里负责什么
Agent，例如 Codex、Claude Code理解要求，读取文件，选择和执行技能
Skill，例如 baoyu-xhs-images规定分析、拆页、选风格、生成和交付的流程
工具或后端，例如脚本、浏览器、图片 API执行文件转换、读取网页、生成图片等具体操作

一个技能通常不只是单独的提示词文件：

因此，安装时要保留整个技能目录。只复制 SKILL.md，可能会在执行到脚本或参考文件时失败。

还有一个常见误解：安装 Skills 并不等于给模型增加了新接口权限。没有浏览器访问能力，它就不能自动操作网页；没有可用图片后端，配图流程也不会凭空生成图片。

Codex 对 Skills 采用渐进式加载：先读取名称和描述等元信息，使用时再加载详细说明。因此，“装得越多，每次都把所有 SKILL.md 全文塞进上下文”并不准确；但技能过多仍会增加发现和选择负担。入门阶段按需安装更容易定位问题。参见 Codex 官方 Skills 文档。

我的起步建议：第一天只安装 baoyu-format-markdown。等它能正确读取文件、生成结果，再加封面或网页采集技能。一次只增加一个依赖，排错会轻松很多。

怎么判断它真的成功了

不要只看聊天里那句“已完成”，检查文件：

  1. article.md 仍然存在，原始素材没有被覆盖。
  2. article-formatted.md 真实存在，标题、列表和命令仍然完整。
  3. frontmatter、正文层级、代码格式能正常显示。
  4. 如果执行了完整分析流程，可能还有 article-analysis.md。

一个重要区别：技能工作流会安排输出文件；直接运行其 scripts/main.ts 是机械排版入口，会处理传入的文件。不要把脚本直接作用于唯一原稿，然后期待它自动完成备份、标题选择和内容分析。

想补充事实、重写论证或增加案例，应另提写作要求。该技能本身要求保留内容，不能因为排版精致就把未经核实的新内容混进去。依据：baoyu-format-markdown 的实际流程。

7.2 公众号：优先把 Markdown 直接交给发布技能

baoyu-post-to-wechat 已内置 Markdown 到公众号内容的处理。当前说明明确要求不要提前把 Markdown 转成 HTML 再套同一发布链路，因为浏览器路径和 API 路径处理图片的方式不同。

API 路径涉及公众号凭证、IP 白名单和 draft/add 等接口；浏览器路径则依赖 Chrome 与有效登录状态。草稿创建成功不等于已经向读者群发。 验收时要明确结果属于哪一个阶段。

只有你需要单独交付带样式 HTML 文件时，再使用 baoyu-markdown-to-html。它和公众号发布技能是不同用途，不必强行串联。

依据：公众号发布技能。

八、排错：按“发现、执行、输出”三层检查

现象先检查什么下一步
Agent 说找不到技能安装范围、当前项目、完整 SKILL.md 路径用 skills list 检查，再显式点名调用
找到了技能，但找不到脚本是否只复制了 SKILL.md安装完整技能目录，保留 scripts 与 references
提示找不到 Bunbun 或 npx bun 能否运行按该技能要求配置运行时
第一次停在偏好选择是否缺少 EXTEND.md按引导完成初始化，确认实际保存位置
修改偏好后没有变化项目配置是否覆盖用户配置，脚本是否读取该路径让 Agent 报告所采用的配置路径，勿打印密钥
网页只能读到登录页Chrome 会话、登录与验证码状态完成必要交互，再重新采集
图片接口返回 401、403凭证、账户权限、请求地址按对应提供商的错误说明排查
图片接口返回 429配额、速率与并发减少并发，检查额度，再重试失败项
提示完成但没文件实际输出路径与脚本日志用文件存在性和可打开性验收
图片压缩后原稿不见是否遗漏 —keep从备份恢复，后续明确保留原图
PPTX 中的文字不能单独编辑是否使用逐页图片合成回到原稿或提示词修改后重生成页面
Hexo 图片 404source 中实际文件和正文公开 URL 是否对应检查大小写、构建产物和线上地址

Windows 还要留意命令所在环境。PowerShell 中的环境变量写法是 $env:NAME = “value”，不能直接套用 Bash 的 NAME=value command；目录含空格时要加引号。教程里出现占位路径时，应替换成实际路径，不能原样执行。

名称中带 danger 的工具，仓库说明涉及非官方或逆向网页接口，使用前应阅读其说明并考虑账户、稳定性和平台限制。它们适合有明确需求时评估，不适合作为入门教程默认依赖。依据：项目免责声明。

九、更新维护：保持可复现，比追新更重要

用 skills CLI 安装的技能，可以查看和更新：

如果装在全局：

用 Claude Code 插件市场安装的，就通过 /plugin 的 Marketplaces 界面更新该市场。不要把“更新 Git 克隆”“更新插件市场”和“更新 skills CLI 的安装副本”当成同一个动作。

对长期写作项目，我建议保留三种记录：

  1. 技能来源与版本或提交号。
  2. 项目级 EXTEND.md 中的非敏感偏好。
  3. 原稿、最终提示词和最终输出文件。

更新后先跑本文的短文排版练习，确认读写与输出路径正常，再处理正式文章。每次只增加少量技能，也方便判断是安装、配置还是内容本身出了问题。
