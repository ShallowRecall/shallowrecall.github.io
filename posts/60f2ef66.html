baoyu-comic实战：把知识点变成可审阅的分镜漫画

发表于2026-10-15|更新于2026-10-15|技术笔记开发工具宝玉Skills
|阅读量:

返回总教程

baoyu-comic 适合把抽象知识变成有角色、有行动、有因果顺序的漫画。它的核心资产不是最后的 PDF，而是内容分析、分镜、角色定义和逐页提示词；这些材料让一次性出图变成可审阅、可修订的制作流程。

本文基于固定提交源码核对；案例是操作示例，非付费服务或账号实测，未实际生成漫画。

一、场景与边界

适合概念科普、人物经历、操作教学和知识故事。例如解释版本控制时，可以用两位同事同时修改同一文件的情境表现冲突，而不是让人物站在画面里连续念定义。

技能分开控制画风、情绪和分格。画风有 ligne-claire、manga、realistic、ink-brush、chalk、minimalist；情绪包括中性、温暖、戏剧化等；布局包括常规、电影感、密集、整页、条漫和四格。预设除了组合这些维度，还可能附带叙事要求，例如四格预设强调起承转合，不能仅把四张无关联插图拼在一起。

边界是“教育性叙事”，不是自动事实核查。真实人物经历、技术原理和引用需要来源，不能为了戏剧性补造事实。输出主要是位图页面与合并 PDF，不是可逐个气泡编辑的漫画工程文件，也不包含发布动作。

二、前置依赖与按需安装

需要能访问资料和输出目录的 Agent、可用的图像后端，以及合并 PDF 所需的 Bun 运行环境。源码规定优先用 bun，没有时可使用 npx -y bun；这只解决运行入口，不表示外部依赖已经全部可用。

仓库提供的安装入口为：

Claude Code 用户可将 codex 替换为 claude-code。

按需选择 baoyu-comic；有原生图像工具时不必重复安装另一套后端。没有后端再考虑 图片生成。安装命令未锁定本文版本；固定版本使用完整源码技能目录，Codex 项目级可放进 .agents/skills/baoyu-comic/。不要删掉 references/ 和 scripts/，前者提供分镜模板，后者包含 PDF 合并入口。

三、输入输出与阶段停止

输入可以是知识文章、人物资料或明确主题。建议同时给出受众、必须保留的术语、允许改编的范围和目标页数，避免 Agent 把技术教程改成过度戏剧化故事。

输出位于 comic/{topic-slug}/，包括：

  • analysis.md：内容分析。
  • storyboard.md：逐页逐格分镜。
  • characters/characters.md：角色定义。
  • characters/characters.png：需要时生成的角色参考表。
  • prompts/NN-{cover|page}-{slug}.md：逐页提示词。
  • 页面 PNG 与 {topic-slug}.pdf。

源码确实支持“仅分镜”“分镜加提示词”“从已有提示词生成图片”“只重生成指定页”等部分流程。自然语言指定即可，不必把技能选项当成系统可执行命令。仅分镜阶段不会生成角色参考图片；不要因为看见 characters/ 目录就假定里面一定有 PNG。

四、可复制的 Agent 请求

续作请求可以写：“沿用已确认的分镜与角色定义，先核实图像后端是否支持参考图，生成角色表后再分批制作页面；每页提示词必须先落盘。”

五、案例：六页合并冲突漫画

第一步把知识链分成六个阅读节点：共同起点、两人同时修改、合并发现差异、理解冲突标记、人工选择正确内容、运行验证。这里的页数是本例目标，不是技能固定模板。

第二步为人物建立少量稳定特征，例如眼镜、发型和衣服主色。多页反复出现的角色建议先生成参考表，标准参考表比例为 4:3；正式页面默认 3:4。角色表与用户提供的风格参考不是一回事：前者约束身份，后者可以约束线条、构图或配色。

第三步审阅分镜。第四页不能只用旁白说“发生冲突了”，应让画面实际展示同一区域有两种修改，同时避免虚构不可执行命令。单格只承载一个核心动作，技术说明过长就拆格，而不是缩小气泡文字。

第四步保存全部页面提示词。每份提示词包含角色、动作、格子布局、对白与页面比例。用户选择了分镜审阅和提示词审阅后，两道关口都应保留；源码中的初始样式确认是必要步骤，后续两项审阅则是条件步骤。

第五步先生成角色表，再出正文页。后端支持参考图时逐页传入角色表；若只支持一张参考图，优先保留人物一致性，把其他风格信息改成文字描述。页面可以分批生成，默认批量四，但角色表依赖不能被并行策略打乱。

第六步逐页验收，再合并 PDF。第三页不合格时，只修改第三页提示词并重生成该页，不必重做整本。修改后必须重新合并 PDF，否则图片目录是新版，交付文件仍可能是旧版。部分流程参考还约定封面编号为 0，正文为 1 到 N，要求 Agent 报告时区分“正文页号”和实际文件名前缀。

六、配置要点

漫画技能在此提交只列出两级偏好路径：项目 .baoyu-skills/baoyu-comic/EXTEND.md，然后用户 $HOME/.baoyu-skills/baoyu-comic/EXTEND.md。不要照搬其他技能的 XDG 三级查找规则。

首次缺少偏好文件时设置是阻塞步骤。可配置 preferred_art、preferred_tone、preferred_layout、language、preferred_image_backend、generation_batch_size，以及角色预设和水印。可以要求 Agent 保存“中文、中性语气、每次确认图像后端”，不要把账号密钥混进角色或风格配置。

语言优先级是当前显式语言、偏好语言、用户对话语言、源内容语言。会话标识仅在后端支持时使用，不是所有后端都有同名能力，更不能用它替代角色参考。

七、验收与排错

  • [ ] 每页推进知识理解，故事动作与原理因果一致。
  • [ ] 人物外观、衣服颜色和关键道具跨页稳定。
  • [ ] 气泡顺序清晰，中文对白可读且无错字。
  • [ ] 每张图片均有对应分镜与最终提示词。
  • [ ] PDF 页序正确，修改页已进入最新合并版本。
  • [ ] 原始资料、参考图授权与事实来源可以追溯。

参考图请求失败：先缩小或转换参考图，重试后仍失败时才回退到角色文字描述，并明确告知一致性可能下降。人物每页变样：检查是否真的传入角色表，而非只保存了文件；增加描述不能完全替代实际参考。对白错误：新建修正提示词和新输出候选，重生成，不用程序在位图上覆盖文字。PDF 缺页：核对编号、文件命名和生成成功数量，再执行合并；不要拿半成品冒充完整漫画。

Obsidian 与 Hexo 展示时使用普通 Markdown 图片和 PDF 文件链接，并确保附件会随发布链同步。不要把提示词备份和含隐私的参考图一并公开。

八、相关技能与源码

社交图片卡片 更适合没有人物故事的知识清单；幻灯片 更适合汇报式展开；图片压缩 可用于合适的参考图与交付图优化。
