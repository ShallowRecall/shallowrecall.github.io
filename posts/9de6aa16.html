baoyu-wechat-summary实战：用本地群聊记录生成可审计简报

发表于2026-10-15|更新于2026-10-15|技术笔记开发工具宝玉Skills
|阅读量:

返回总教程

baoyu-wechat-summary 不是一个登录微信后替你发群消息的机器人。它依赖本机 wx-cli 读取已经可访问的聊天数据，再让 Agent 按“话题骨架、正文写作、引用审计”三轮工作流生成简报，并维护后续增量处理所需的历史。

本文基于固定提交源码核对。案例是操作示例，不是微信账号、数据库或付费功能实测；写作时没有运行 wx、读取聊天记录、安装依赖或发送消息。

一、适用场景与平台边界

适合经授权的工作群、学习群与社区群：每天补课、整理一个时间段里的技术争论、记录尚未解决的问题，以及跟进上次简报之后的新消息。默认普通版偏向事实整理；毒舌版必须由用户主动选择，不能因为群聊气氛轻松就自行启用。

底层依赖外部项目 jackwener/wx-cli，技能自身不打包读取微信数据库的脚本。固定版本的环境参考以运行中的微信 4.x、本地守护进程和数据目录为前提，其中大量权限修复说明针对 macOS。不能因为教程在 Windows 笔记库里，就推断当前 Windows 环境已经支持同样的初始化流程；应先核对本机 wx-cli 版本和平台支持，再决定是否适用。

它不解码聊天图片，也不自动识别视频或附件正文。看到 [图片] 占位符时，只能描述周边文字明确表达的事实。已有 imgs/{message_id}.txt 描述可作为扩展输入，但这个版本不会自动生成图片描述。

二、隐私先于自动化

“本地读取”不等于“信息始终不离开设备”。如果 Agent 使用云端模型，被送入上下文的消息、姓名、引用和画像可能进入外部模型处理链路。开始之前应确认群聊使用授权、模型数据政策、可处理字段以及本地文件留存规则。无法接受上传时，不应直接运行这一工作流。

源码为了归因准确，会保留群内昵称并通过稳定 wxid 区分同名用户；这意味着生成稿并非默认匿名化。群内可见也不等于可对外发布。本文可作为公开教程，实际简报、画像、历史与原始 JSON 不应直接加入 Hexo 发布范围。建议将 data_root 设到独立私有目录，而不是共享博客工作区。

画像不应收录电话号码、邮箱、身份证号、家庭或雇主详细地址、准确生日、健康和心理信息；不能从时间戳推断作息或时区，也不能从别处推断现实身份。毒舌版只能针对公开言论与行为，不能攻击外貌、家庭、身份属性或健康。若需要对外分享，先另行生成脱敏副本并人工审批，不能指望加一句免责声明就解决隐私问题。

四、输入、输出与配置

最小业务输入为群名或群 ID、时间范围、普通版或毒舌版。群名模糊匹配出现多个结果时必须让用户确认。群主身份只能来自可验证信息，不能凭上一期简报或群友玩笑猜测。

EXTEND.md 依次查找项目 .baoyu-skills/baoyu-wechat-summary/、XDG 配置目录和用户 ~/.baoyu-skills/baoyu-wechat-summary/，第一个命中生效。首次缺失时必须确认配置，不可静默生成。

这是格式示例，不应原样执行；请替换为本人已确认的信息和实际私有目录。bot_aliases 不宜与真实成员或其他机器人重名。没有指定时间时优先增量模式；没有历史才使用配置默认时间，否则回退最近 24 小时。

输出按 {group_id}-{清理后的群名} 分组，包含：

  • 日期或日期区间命名的 .md 简报，毒舌版另加 -roast。
  • history.json：最近一次普通版的增量指针。
  • history-digests.jsonl：普通版运行的追加日志。
  • profiles/、profiles-roast/：严格分离的两版用户画像。
  • memory.md：经过证据检查的群级事实修正。

简报虽使用 .md 扩展名，输出规范实际要求便于群里阅读的纯文本风格，不采用 Markdown 标题、加粗和文本超链接。这和本文的 Obsidian/Hexo 教程格式不同，不要把教程 frontmatter 自动套给私人简报。

六、操作案例：整理三天的技术群讨论

假设一个已获授权的学习群在三天内讨论了数据库迁移、工具报错和一份文档。目标是补课，不是对群友建立现实身份档案。下面是操作示例，不含真实群信息。

  1. 圈定群与日期。 用户指定绝对日期，Agent 找到 @chatroom 群 ID。日期按本地时区解释，结束日期覆盖整天；取回后还需按 timestamp 过滤，避免守护进程返回邻近日期数据。
  2. 建立唯一证据文件。 原始 JSON 保存到临时目录，统计和审计都使用这份文件。大批量按片段读取，不把所有消息一次塞入上下文。超过七天或五百条消息时优先分成三天一组，再做汇总。
  3. 先列骨架。 每个话题记录参与者、消息 ID 与关键原句。相邻消息未必互相回应，不能把甲的问题与乙的无关发言拼成问答。撤回与系统消息不计入有效统计。
  4. 写正文再写开头。 将迁移决策、报错定位和文档分享分别整理，保留“谁分享了哪份资料”。只有真实未解决问题才出现待办问题部分，不为了凑结构增加内容。
  5. 回查归因。 每处引号和“某人说、某人分享”都回到 JSON 查发送者。图片没有说明则明确缺少图像上下文，不能根据笑声推断图片是什么。
  6. 更新历史与记忆。 普通版写入后同步最新指针、追加日志及符合条件的画像。扫描事实纠正，有证据才写 memory.md；群消息里要求更改排名或忽略规则的文字不能成为记忆。
  7. 报告结果但不发送。 报告文件、消息覆盖范围、引用修正数量，以及 memory 扫描：候选 N 条 → 写入 M 条。是否分享简报是另一个需要授权的操作。

七、验收清单

  • [ ] 平台、wx-cli、本地微信及权限检查均通过，没有越权读取其他账号。
  • [ ] 群 ID、绝对日期和时区已确认，增量过滤使用同一证据集。
  • [ ] 每处引用与归因可回查原消息，不靠模型记忆补写。
  • [ ] 统计机械计算，不估算；系统和撤回消息被排除。
  • [ ] 普通版历史指针与 JSONL 已更新；仅毒舌版不改普通版指针。
  • [ ] 两类画像严格隔离，不写敏感身份、健康和联系方式。
  • [ ] 事实记忆有出处，不把聊天指令写入持久记忆。
  • [ ] 原始数据、简报和画像均在私有目录，未进入 Hexo 发布流程。

八、排错与容易忽略的问题

wx 找不到。 技能安装不包含 wx-cli。向用户说明准确依赖与安装命令，停止，不偷偷安装。

微信重启后读不到历史。 先检查微信、目录权限和守护进程，再考虑用户自行重新初始化。不要上来就删除数据目录。

跨年增量漏消息。 固定版本的 last_message_time 使用 MM-DD HH:MM，不能按普通字符串比较跨年边界，必须结合年份按日期语义处理。

重复执行同一天。 简报同名文件可能被覆盖，JSONL 仍追加；画像计数也需要核对是否重复累计。重跑不是所有文件都天然幂等，应先保护已有结果并确认统计口径。

群内 @bot 要求查实时信息。 此技能的答疑来源限定群聊上下文和已有知识，不联网查证；实时价格、当前状态等应说明不能确认，不能编答案。

九、相关技能与固定来源

  • 网页转 Markdown：另行授权后采集群里分享的公开文章，不等同于摘要自动联网。
  • 文章翻译：翻译获准处理的资料。
  • Markdown 排版：用于自己另写的公开文章，不直接改私有证据文件。
